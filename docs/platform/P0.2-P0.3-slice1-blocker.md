## BLOCKED-F01 — required triggers excluded by exact inventory

1. Final Platform Implementation Specification v1 §4.6 requires DB trigger guards for account provider binding and role assignment identity/role/origin. It explicitly says application code is not the sole immutability control.
2. v1.1 §3.1 requires DB checks/trigger guards binding role assignment and revocation attribution to the current actor.
3. v1.2 §3 says: “Every function not listed below is forbidden until Security review updates this inventory.” Its exact inventory includes no function returning `trigger`.

PostgreSQL trigger guards require a trigger function. A row CHECK cannot compare OLD and NEW state to enforce immutable provider binding and role history. Column grants do not replace the specifically required trigger guard. Adding unlisted functions, weakening immutability, or moving helpers to another schema to avoid review would violate the contract.

Impact: the identity/authorization migrations cannot be completed consistently with both requirements. This is an implementation-contract conflict, not a Product Contract redesign or request to change core progression.

Required next owner: Security Lead, followed by Director reconciliation. See `P0.2-P0.3-slice1-security-handoff.md` for the smallest proposed correction. No correction is approved by this report.
